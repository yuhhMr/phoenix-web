# Phoenix-Web 开发工作流

本 skill 约束在 `phoenix-web` 项目中的编码与推进方式，避免上下文丢失导致的重复 bug 和返工。

## 核心原则

1. **不用 subagent 做 UI/页面级工作**
   - 精细的 UI 改动、页面重构、组件迁移必须由主线直接完成。
   - subagent 只能用于纯只读探索（如查文件、读源码），且探索结果需人工复核。

2. **改共享组件前，先定位所有消费者**
   - 修改 `src/components/ui/*` 前，必须先用 Grep 搜出所有 `.vue`/`.ts` 使用者。
   - 理解每个使用者的当前行为和期望行为后再动手。

3. **一次只聚焦一个可验收单元**
   - 单元可以是一个页面、一个组件、一个修复。
   - 该单元必须达到“功能正确 + 视觉正确 + 静态检查通过”才能进入下一单元。

4. **UI 改动必须肉眼验证**
   - 静态检查（type-check / lint / build）通过后，必须起 `npm run dev` 看实际页面。
   - 检查点包括但不限于：布局、padding、按钮重复、交互状态、空数据、错误提示。

5. **每个验收点做记录**
   - 完成一个单元后，向用户汇报：改了什么、验证项、commit hash。
   - 不要批量合并多个主题的改动到一个 commit。

## 具体执行流程

### 修改组件前

1. `Grep` 或 `Bash rg` 搜出该组件所有 import/use。
2. 列出影响清单（至少文件名）。
3. 阅读关键消费者（尤其是登录页、高频页面）。
4. 决定是改组件本身，还是改消费者，还是两者都改。

### 修改页面时

1. 一次只改一个 `src/views/**/index.vue`。
2. 改完后运行：
   - `npm run type-check`
   - `npm run lint`
   - `npm run build`
   - `npm run dev`（实际查看页面）
3. 按检查清单逐项确认（见下文）。

### 检查清单（最小集）

- [ ] 页面能正常加载，无控制台报错。
- [ ] 输入框：placeholder、clear 按钮、密码可视化、focus 状态正常。
- [ ] 按钮：hover、disabled、loading 状态正常。
- [ ] 表格：loading、空数据、分页、操作列正常。
- [ ] 弹窗：打开、关闭、保存、取消正常，无层级/定位问题。
- [ ] 表单提交：Enter 不双触发，错误提示正确显示。

### 提交规范

- commit message 用 conventional commits。
- body 每行不超过 100 字符（受 commitlint 约束）。
- 一个 commit 只对应一个主题（如 `fix(login): ...`、`feat(user): ...`）。

## 禁止事项

- 不要在没有 grep 影响面的情况下改 `src/components/ui/*`。
- 不要一次性迁移多个视图。
- 不要用 subagent 生成/修改 `.vue` 文件。
- 不要只做静态检查就声称页面完成。
